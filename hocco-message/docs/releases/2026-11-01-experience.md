# HOCCO experience proposal implementation

Public pages share DM Sans interface typography, common control dimensions, visible focus, dark surfaces and responsive cards. Navigation uses Assistir and Empresas. The hero retains participation, YouTube, classification and voluntary audio; five illustrations rotate and all ten remain in the series gallery. Hero media is loaded progressively. The essential service worker shell no longer preloads video and all artwork.

The profile combines recent video and community purchases and keeps local-only storage explicit. Avatar keyboard navigation preserves ten choices. The sponsor directory separates empty inventory from empty filters and exposes the national reset. Registration validates required fields and HTTPS links, presents a review before the existing submit handler, and preserves the original terms and dynamic prices. LIVE availability reflects its actual schedule and open queue.

Sponsor retries recover by private tracking hash before uploads, use unique non-overwriting paths per attempt, and check references before cleanup. A committed operation with a lost response is recovered. The payment UI honors the existing 48-hour sponsor reservation and archived/hidden/financial states. No customer purchase or refund was made for validation.

The additive migration installs service-only anonymous daily interaction counters and two supporting indexes. The control shows actions, explicitly not unique people or conversion rates. The existing measurement opt out also disables these action counters. No new user or visitor identifiers are stored. Security warnings remain unchanged; the intentionally service-only metrics table adds an informational RLS-without-public-policy notice.

Validation: unit and runtime suite; isolated upload failure, retry and concurrency cases; transactional counter and privilege assertions; public browser verification of navigation, gallery, ten avatars and registration. Core Web Vitals targets and business conversion effects require subsequent representative measurements; no achieved score or sales uplift is claimed. Optional account synchronization, personalization and new notification campaigns remain separate product work.

Rollback: redeploy the prior frontend commit and prior Edge Function version if needed. Keep the additive metrics table and indexes; removing them is unnecessary for restoring the old interface. Do not roll back by deleting orders, assets or financial records.
