# Security hardening

45 legacy SECURITY DEFINER routines were moved, keeping original OIDs and bodies, into hocco_rpc_internal. Public SECURITY INVOKER entry points preserve signatures, defaults, return types, volatility and authenticated access. Anonymous execution stays revoked. Only schema usage and the required internal routine executions are granted to authenticated; no table access or schema CREATE was granted. The internal schema must remain outside PostgREST exposed schemas.

The existing per-user and administrator guards remain inside the original implementations. Preflight transactions compared all 45 entry points before and after the move both without a user ID and with an unrelated synthetic user ID. No financial action or notification was executed. Existing hm_ server routines were untouched. New postgres-created routines no longer inherit PUBLIC execute permissions; future migrations must grant necessary access explicitly.

Hosting headers now include frame-ancestors none, X-Frame-Options DENY, HSTS without preload or includeSubDomains, and same-origin opener isolation. The application uses redirect checkout and external noopener links rather than cross-origin opener messaging.

The API reads JSON through a byte-bounded stream, rejecting oversized declared or streamed requests before database or payment operations. The existing tighter limit for ordinary actions remains. Sponsor payloads retain room for both permitted images.

Leaked password protection was not enabled: the organization is on Free and Supabase documents this capability as Pro and above. No plan or recurring charge was changed. Existing RLS-without-policy notices describe intentionally service-only tables rather than missing public access grants.

Rollback of the legacy isolation must remove each new public invoker wrapper before moving its internal implementation back to public, then restore its explicit authenticated grant. Do not drop internal implementations or use CASCADE. Reverting default privileges requires a separate reviewed migration. Header changes can be rolled back by deploying the prior commit.
